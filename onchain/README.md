# DoubleTake strategy program

The program is a release candidate. No public deployment is recorded. The address
in the source and `Anchor.toml` is a development placeholder and must never be used
to enable production funding. Do not deploy or sign on mainnet from build scripts.

## Reproducible build

Rust dependencies are locked in `Cargo.lock`; every Anchor component is pinned to
1.0.2 to match Raydium's pinned source. Raydium CLMM is revision
`ed1eb41519d5355755f7df52b43fa9610938b60b`; its instruction implementation is used
through the typed `SwapSingleV2` CPI, never a caller-supplied program or arbitrary
instruction buffer. Agave CLI 3.1.10 is the build pairing. The Anchor CLI on the
developer host may differ; the Cargo and SBF builds below use the pinned crates.

```sh
cd onchain
NO_DNA=1 cargo test --locked
NO_DNA=1 cargo build-sbf --manifest-path programs/doubletake/Cargo.toml --sbf-out-dir target/deploy
sha256sum target/deploy/doubletake.so
```

The complete checked-in runner supports native Linux and Windows with WSL. It
selects the Windows Node runtime when dependencies were installed on Windows and
uses a persistent Linux build cache rather than a volatile RAM-backed `/tmp`.

```sh
bash onchain/scripts/test.sh --unit # Rust + independent client security checks
bash onchain/scripts/test.sh --sbf  # also build SBF + offline owner controls
bash onchain/scripts/test.sh --fork # also build SBF + local mainnet-fork cycles
bash onchain/scripts/test.sh --all  # all suites
```

From PowerShell, `npm run test:program -- --all` runs the same script in WSL Ubuntu.
The script starts isolated Surfpool RPCs on loopback ports 18089/18099, downloads
public mainnet state for the fork, and stops its own processes on exit. Both TS
harnesses reject every non-loopback RPC before signing. Test keypairs only exist in
memory. No public-cluster transaction is sent. `FORK_RPC_URL`/`LOCAL_RPC_URL` can
override the loopback ports.

The fork suite runs SOL and AAPLx by default. Set `FORK_ASSET_SYMBOL=SOL` or
`FORK_ASSET_SYMBOL=AAPLx` to select one fixture. The AAPLx case exercises the
actual Token-2022 mint, public issuer extensions and native Raydium CPI. The
fixture creates a gap with bounded local swaps; it does not claim a current
live-market opportunity. A changed mainnet pool can invalidate fixture depth,
in which case the test must stop rather than invent a successful route.

From Windows run these commands in WSL Ubuntu. Keep target artifacts and ephemeral
local-test keypairs outside version control. A release records compiler versions,
the lockfile, program bytecode hash, cluster, real program address and upgrade
authority. Deployment identities are supplied at rollout, not generated by this
repository.

## Operator setup preparation

`shared/program.ts` exports exact unsigned administrator instruction builders.
The preparation script verifies the RPC genesis, executable program, canonical
ProgramData, bytecode hash and actual administrator/upgrade authority, then writes
an unsigned transaction and an account-by-account review record. It never reads
private keys, signs, funds or broadcasts a transaction.

Before a production build, replace `declare_id!` in the Rust source and the
corresponding addresses in `Anchor.toml` with the founder-owned program public
key. Rebuild SBF, record its hash and independently verify the deployment. The
development `Fg6...` identity cannot be used for mainnet bootstrap preparation.

```sh
node --import tsx onchain/scripts/prepare-admin.ts \
  --rpc http://127.0.0.1:8899 --cluster localnet \
  --program YOUR_DEPLOYED_PROGRAM_PUBLIC_KEY --admin YOUR_ADMIN_PUBLIC_KEY \
  --action initialize-config --keeper YOUR_DEFAULT_KEEPER_PUBLIC_KEY
```

After an operator reviews and signs through their wallet, prepare `register-asset`
with `--asset AAPLx` (or another exact registry symbol), and `create-invite` with
`--owner INVITED_OWNER_PUBLIC_KEY`. Registration and invites can be prepared while
config is paused. `set-config --keeper PUBLIC_KEY --paused false` prepares the
explicit launch action only after the documented release gates are satisfied.
`set-invite --owner PUBLIC_KEY --enabled false` revokes admission;
`refresh-asset --asset SYMBOL --enabled true` increments the security revision and
requires every affected owner to reauthorize. No setup script enables automation
by itself. Prepared blockhashes expire; regenerate a preparation before review.

## Authority and capital model

Config initialization proves the actual program's upgrade authority from its
canonical loader ProgramData PDA. Config starts paused. Administrator invitations
are capped at five active owners. Asset registration checks a hardcoded seven-mint,
fourteen-pool registry and validates both actual Raydium pool mint pairs.

Owner vault PDAs use `["vault", owner]`; USDC and intermediate accounts are canonical
ATAs. Owners sign initialization, deposits, configuration, pause, withdrawals and
recovery. The owner explicitly authorizes the user's isolated fee-wallet keeper.
The keeper can only execute guarded cycles, with no withdrawal instruction.
Canonical ATAs may already exist before the vault: initialization validates and
reuses them, preserving unsolicited balances while accounting for zero initial
principal. The vault state itself is initialized exactly once per lifetime.

The deposited-principal cap is 100 USDC. Cycles use at most 25 USDC, at least 0.05
USDC profit, 60-second cooldown, ten cycles per UTC day, and permission expiring
within 24 hours. Execution consumes an exact nonce and a deadline within 40 slots.
Withdrawals revoke the permission and increment the nonce. Unsolicited ATA gifts
remain recoverable by the owner but never increase authorized cycle capital.

Two exact-input Raydium swaps execute atomically. The second leg uses the actual
received raw integer amount. Postconditions check profit, zero new intermediate
inventory, account authorities, delegates, close authorities and issuer metadata.
Network fees are charged by Solana even if these postconditions revert the cycle.

Pause/withdraw/recover/close have no service configuration, email, database or
worker dependency. Close returns rents to the owner after both ATAs are empty;
closing on a day with confirmed cycles is prohibited to avoid resetting the daily
cap; the 60-second cooldown also survives a midnight boundary. The canonical
invite retains a monotonically increasing nonce seed across vault closure and
recreation, even when admission is disabled. Close requires that owner-scoped
record without requiring an active invite or service config. Owner recovery
remains subject to issuer freeze/hook restrictions on the
asset itself. USDC withdrawal is separate from intermediate-asset recovery.

## Token-2022 policy

The SHA-256 issuer fingerprint covers mint/freeze authorities, decimal precision,
token program and normalized approved extensions. Supply and active multiplier
values are excluded from the security hash, while multiplier authority is included.
Execution is blocked for fifteen minutes before and after a scheduled multiplier
activation. Fingerprints are retained in cycle events.

Approved issuer control extensions include permanent delegates, mint-close
authority, metadata/group pointers, confidential-transfer mint configuration for
**public** accounts, null transfer hooks, scaled UI amount and an unpaused pausable
mint. Unknown extensions, transfer fees, active hooks, confidential account
balances, frozen/paused accounts and non-transferable tokens block execution.
An admin security refresh increments the asset revision so owners must reauthorize.

## Verification gates

Unit tests cover caps, integer arithmetic, replay, deadlines, cooldown, daily limits,
gift accounting, exact-pool admission, extension policy and multiplier boundaries.
Client tests prove independent instruction reconstruction rejects substituted
recipients, changed amounts, extra instructions, excessive network fees and opaque
lookup tables.

The fork harness clones the actual approved SOL/AAPLx Raydium pools/program and creates
a controlled gap using a real local swap. It verifies the profitable cycle, actual
received-token handoff, failed second-leg rollback (both pools and both ATAs), fees
on the processed failure, replay rejection and profit accounting. It uses a real
confirmed local Address Lookup Table for the complete v0 transaction. It also
executes real owner initialization, deposit and keeper configuration, checks the
deposit cap, and exercises the product gateway's complete simulation, signing,
submission and receipt reconciliation against the local bank. AAPLx additionally
checks scheduled multiplier activation. Frozen intermediate accounts and missing
tick arrays are rejected without changing principal. Exact recorded results are
in `VERIFICATION.md`; a suite description is not a claim that a run passed.

Production funding stays disabled until independent engineering review and the
release's bytecode hash, upgrade authority, deployment/configuration, issuer
eligibility, canary and these runtime tests have been verified. Host tests or a
successful SBF compilation do not establish those gates.
